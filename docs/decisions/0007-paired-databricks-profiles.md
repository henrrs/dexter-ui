# ADR 0007: Paired Databricks profiles with shared local authentication

- **Status:** Accepted.
- **Context:** Dexter needs separate DEV and PRD workspace coordinates while allowing the same local identity to authenticate to both without copying credentials into Dexter.
- **Decision:** `make databricks-setup` gathers two HTTPS workspace hosts, reuses one active Azure CLI tenant/session, validates current-user access to both workspaces, then writes `DEXTER-DEV` and `DEXTER-PRD` to Dexter's private Databricks config file. Both profiles use `auth_type=azure-cli`; the Azure CLI owns the shared credential cache. Profile config is kept separate from the standard user Databricks config. Existing profile names are protected; changing Dexter-owned profiles requires `RESET=1` and makes a private backup. The profile environment mapping is recorded in a token-free state file.
- **Consequences:** No shell environment variables or PATs are required for setup. The shared login does not combine workspace grants: DEV and PRD remain independent, validated connections. Profiles for other auth providers and tenants are outside this setup flow. Failure to validate either workspace leaves both profiles unchanged.
- **Implementation:** `backend/src/dexter/adapters/databricks_setup.py`, `scripts/databricks_setup.py`, and the `databricks-setup` Make target. The SDK's `config_file`, `profile`, `auth_type`, and `azure_tenant_id` options are used as documented in the [Databricks SDK authentication reference](https://github.com/databricks/databricks-sdk-py/blob/main/docs/auth-types-reference.md) and [authentication guide](https://github.com/databricks/databricks-sdk-py/blob/main/docs/authentication.md).
