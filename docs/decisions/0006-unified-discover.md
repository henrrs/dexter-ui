# ADR 0006: Unified Discover cache and provider boundaries

- **Status:** Accepted for the F2 implementation; remaining integration gaps are documented below.
- **Context:** Discover must read metadata from local snapshots, Databricks DEV/PROD, and Purview without persisting credentials, scanning everything at startup, or treating metadata visibility as read access.
- **Decision:** Load each provider independently and lazily by hierarchy. Store returned metadata pages in SQLite WAL with separate contexts and TTLs (catalog 6h, schema 30m, table 15m, detail 1h; Purview assets 6h). Local snapshots are accepted only when their manifest and data file resolve inside the local datasets directory. Databricks `browse_only=true` means metadata-only, `false` means table read access, and missing evidence means unknown. Purview uses the configured endpoint and current Azure CLI identity against Unified Catalog Data Assets; no Atlas or alternate-identity fallback is attempted. A canonical match requires metastore ID plus an exact fully qualified Databricks name, or the equivalent Databricks FQN from Purview.
- **Consequences:** Provider failure does not erase successful cached pages; stale cached data is returned with an error marker when the provider context is known. The UI keeps provider trees separate and shows a Purview governance match on a selected Databricks asset only when its metastore ID and full qualified name match exactly. Purview currently consumes only one page (up to 100 assets); nextLink pagination, full source-specific access state, a single canonical tree, local/remote previews, and server-side request deduplication remain pending. Cache contexts are hashed; tokens and secrets are never persisted.
- **Evidence:** Databricks Unity Catalog list APIs expose pagination and `browse_only`; effective permissions can be inherited and are not queried per table. Microsoft Unified Catalog Data Assets is a preview API. The implementation therefore reports unknown when evidence is incomplete and records the API limitations in the UI and docs.
